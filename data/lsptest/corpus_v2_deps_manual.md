# Second corpus: dependencies installed by hand (2026-11-18)

The frozen preparation (`scripts/paper/corpus2/prepare_corpus2.py`, which runs the frozen `scripts/lsptest/prepare_corpus.py`) clones each project at its pinned commit, installs dependencies with the project's own package manager without install scripts, and probes the servers. For 4 of the 40 projects the dependency step failed. Its rule takes the package manager from `packageManager` in package.json, else from the lockfile (pnpm-lock.yaml -> pnpm 10); it does not read `engines`. Three were installed by hand under the same rule (the project's package manager, no install scripts) and forced in `data/lsptest/campaigns/main_v2.json`; one stays out. After each install, `git status` shows no change to tracked files and no new untracked file outside ignored paths, and the frozen probe was rerun (`prepare_corpus2.py --only-repo <repo> --skip-deps --force-probe`; the records therefore say `deps_status: skipped-by-flag`).

| Project | Why the frozen step failed | Install by hand | Re-probe (ts6 / ts7) |
|---|---|---|---|
| umami-software/umami@12ad773d621f | pnpm 10 refused: `engines.pnpm` is 12.3.4 | pnpm 12.3.4 (published 2026-09-04), `pnpm install --ignore-scripts --frozen-lockfile` | settled, 0 errors, 0 import noise |
| pear-devs/pear-desktop@3ff0a86231fe | pnpm 10 refused: `engines.pnpm` is >=11 | pnpm 11.27.1 (the latest 11.x on 2026-09-23), `pnpm install --ignore-scripts --frozen-lockfile --config.engine-strict=false` (the workspace sets engineStrict and the build tool node-gyp 13.0.0 asks for Node ^24.15, the machine has 24.3.0; no install script runs) | settled, 0 errors, 0 import noise |
| vadimdemedes/ink@02ae1e59e7c2 | no lockfile (the repository sets `package-lock=false`), so nothing was installed | npm 11, `npm install --ignore-scripts --no-audit --no-fund --before=2026-09-23T23:59:59Z` (only versions published by the pin date; 838 packages) | settled, 0 errors, 0 import noise |
| colinhacks/zod@34a626f30787 | `packageManager` is nub@0.8.3, which corepack rejects ("Unsupported package manager specification") | not installed: nub@0.8.3 is not on the npm registry; pnpm 10.34.5 rejects the lockfile (no entry for the workspace package zod@4.6.5); npm rejects the `workspace:*` protocol | excluded by the campaign's eligibility rule (deps failed) |

The pnpm builds used for the installs were installed into a scratch folder with `npm install pnpm@<version>` (corepack 0.33 cannot run pnpm 12, which ships a native binary). Logs of the installs were kept in the session scratch folder only; the commands above reproduce them.
