## Tool artifacts found and fixed during the pilot

- Contextual keywords were targets: the tokenizer knows only reserved words, so `from` in `import {...} from './util'` became a completion target and every identifier replacing it broke the import (16 findings on the ts6/ts7 fixture). Fixed: a position where renaming the word to word+'x' already breaks the syntax is not an identifier position and is skipped.
- The editor filter accepted any subsequence (`from` matched `CSSTransformComponent`); it now requires the first typed character at a word start of the label, as editors do.
- Module items insert a path prefix (`i32::`), unfinished by design, and were flagged as syntax errors; items whose inserted text ends in `::`, `.` or `/` are now skipped (path-prefix-item).
- R6 hover: typescript-language-server echoes `import X` after an `(alias)` line; the echo is dropped from the compared type text.
- R6 hover: ts6 renders JSDoc @default values in a second code fence, ts7 as text; comparing every fence gave 4 false differences on redux. Only the first fence (the signature) is compared now.
- R6 completion: auto-import suggestions differed at most completion positions (both directions: ts6 offered exports of `typescript` and of Node's ambient modules, ts7 package subpaths such as vitest/node and rolldown) and masked the in-scope labels. They are now excluded from the comparison with the engine's marker (completion_kind.is_auto_import, which the completion normalizer also uses since this pilot; its ts6 case, unresolved typescript-language-server items marked only by sortText U+FFFF+'16', was added from this pilot's data); each run notes at how many positions the excluded sets differ.
- Command-only quick fixes: pyright's createtypestub writes stub files; only commands known to compute an edit and nothing else are followed (EDIT_ONLY_COMMANDS).
- rust-analyzer could not format: the default rustup toolchain lacks the rustfmt component. R4 sessions override rust-analyzer's rustfmt command with the rustfmt of the installed 1.98.1 toolchain (same rustc build as stable) and the project's edition.
- The first Rust fixture had only rustc-lint diagnostics (unused variables/imports), which rust-analyzer does not report with checkOnSave off; the fixture now has diagnostics rust-analyzer computes itself.
- Seeded M2 misspelled declaration targets in comma lists (`output, err :=`, `for name, ok := range`), which declares a new name instead of breaking a use; the findings were the mutation's own leftover errors. Comma-list assignment targets and loop variables (`:=`, `=`, `in`) are no longer M2 sites.
- Seeded replay compared the recorded fix ops read back from JSON (lists) with Op.to_json() (tuples) and never reproduced; it now compares Op objects.

## Known limits

- No corpus target file had a diagnostic with a quick fix, so quick fixes were exercised on the fixtures only.
- Python's parser reports the first syntax error only; before/after comparison is by message, positions ignored.
- Completion findings are confirmed in a fresh session on the original content; the running session had no edits then, so an unconfirmed one is dropped as nondeterminism rather than filed as r1-suspect.
- No edit-based finding occurred, so r1-suspect filing ran only in unit tests and a synthetic replay.
- R6 intended-difference rules encode CHANGES.md (compiler changes: JavaScript/JSDoc, checker, parser); it says nothing about language-service presentation, so no pilot candidate matched a rule.
- R6 does not compare auto-import suggestions (see above), so a server that loses an auto-import source entirely goes unnoticed by R6.
- Seeded quick fixes: rust-analyzer's own diagnostics (checkOnSave off) do not report unresolved imports or names or unused bindings, so M1, M2 and M4 create no diagnostic there; only M3 (missing arguments, missing fields) does. pyright offers no quick fix for the diagnostics the mutations create.
- The seeded errors check compares with the pre-mutation error count, as specified, so a fix that leaves another error of the same mutation is reported; the case records the errors the fix itself introduced, and findings without any are classified legitimate.
- Mutations are lexical (per-language patterns, validated by the syntax classifier); a mutation that creates no diagnostic is counted and skipped.
