# R1 pilot (2026-09-23)

R1 (history independence) on one prepared corpus project per first-batch server, seed 2, 6 histories per run, settled timing plus one race0 run (pyright). The families, in the seeded order, are H2 H3 H7 H5 H4 H8 (H1 and H6 occur only as parts of H7 in this budget). Every candidate is replayed 3 times from scratch (fresh baseline, fresh control, fresh history session), for at most 2 candidates per signature. Only 3/3 with a stable control counts. One confirmed violation per history is reduced with ddmin (32 probes or 1 h; rust-analyzer 12 probes) and re-confirmed 3/3. Seed 2 is used everywhere because seed 1 picks only rustlings exercise files, which belong to no crate. Machine data: `r1.json` (`final_run`, `first_run`, `ts6_no_guard_check`, `classification`, `smoke_lead`).

Run line: `python3 scripts/lsptest/validate_known_bugs.py --pilot` (writes `r1.json` `runs`; this report and the classification were written from it).

Generator version: this pilot ran with families H1–H8. H9 ("edit inside a workspace window") was added after known-bug validation run 1 and the R1 tool was frozen after that change (see `data/lsptest/validation/known_bugs.md`, "Generator change after validation run 1"). The pilot was not rerun: with nine families the seeded round-robin order changes, so a rerun would execute different histories, and the frozen tool's numbers on real projects come from the campaign.

## Confirmed candidates

**gopls v0.23.0: duplicated quick fixes after a configuration change (likely-real).**
- **History:** H4 toggles `gopls.semanticTokens` true → false → back, with `command_win.go`, `doc/rest_docs.go` and `powershell_completions_test.go` open.
- **Difference:** at 8 diagnostic ranges of `doc/rest_docs.go` (unusedparams diagnostics), `textDocument/codeAction` returns 18 actions instead of 14. `Remove unused parameter "name"` and `Rename parameter to "_"` (both quickfix) appear three times each; a fresh session with the same final settings returns them once.
- **Confirmation and reduction:** 3/3 in both pilot runs, reduced 5 → 2 ops (`open command_win.go`; `set_config {"gopls": {"semanticTokens": false}}`), re-confirmed 3/3.
- **Server log:** a fresh session started with `semanticTokens=false` logs `Created View` twice: the default view, plus the GOOS=windows view that the `//go:build windows` file needs. The reduced history logs it 5 times: 2 at start and 3 after its single `didChangeConfiguration`. In the unreduced history the toggle back adds 4 more (views #6–#9).
- **Reading:** each configuration change rebuilds the views with one more than before, and the extra view duplicates the fixes. This deserves an upstream check before reporting (gopls v0.23.0, cobra, any setting change).

**gopls completion at `doc/rest_docs.go:57:28` (flaky, not confirmed).** Two candidates (after H2 and after H3) replayed 1/3 and 2/3. In the failing replays the fresh control itself was unstable on the key: gopls completion varies between fresh sessions, as the engine smoke found. Logged as flaky; no report.

**ts6 6.0.3: stale "zustand has no exported member 'create'" after a rename round trip (first run; tool-artifact, fixed).**
- **History:** H7 nests an edit of `tests/immer.test.tsx` (insert `}` at 51:1, delete it) inside a rename round trip of `src/react.ts`.
- **Symptom:** the first run confirmed `diagnostics:extra:2305,7006` and `codeAction:extra` 3/3 (reduced 7 → 6 ops). TS 7 on the identical ops showed nothing.
- **Session log:** the rename back went out at 15.2 s. PushSettle returned "published and quiet" at 17.2 s, because the last publish for `immer.test.tsx` (13.2 s) was newer than its last didChange, so no fresh publish was required. The snapshot read the stale TS2305/TS7006, and the server published `[]` for the file at 18.4 s, during the query suite.
- **Cause:** typescript-language-server ignores the client's `didChangeWatchedFiles` unless `tsserver.useClientFileWatcher` is set. tsserver therefore learns of the rename from its own file watcher about 3 s later, which is systematic, so all 3 replays agreed.
- **Fixes:**
  - `oracles/r1_history.py`: waits max(6 s, 3 × quiet_seconds) before the snapshot of any history or chain step that contains `fs_write`, `fs_rename` or `set_config`. The wait is not part of the recorded ops, and replay applies the same rule.
  - Engine (main, `ops.py`): workspace-level notifications now require a fresh publish per open document, or 10 s of silence.
- **Checks:** ts6 with the guard switched off and only the engine fix: 0 candidates; in that run the settle after the rename back waits, and the server republishes the file as `[]` 4.1 s later. Final run with both fixes: 0 candidates.

## The engine-smoke pyright lead

The edit / full query suite / inverse / query round trip was run again on pyright 1.1.414 (flask fixture, seed-1 targets). Both snapshots settled and no key differs. The raw top-50 completion labels, taken before any normalization, are identical at all 36 completion keys. The earlier 2/2 difference was in auto-import completion items only, which pyright looks up under a time and count bound: a cold session under load returns fewer of them than a warm one. **legitimate-difference**, and no longer compared: the engine's completion normalizer drops auto-import items (`completion_kind.py`).

## Tool artifacts found and fixed during the R1 work

- **jdtls null answers (engine; fixed by main in `lsp_repro/lspclient.py`):** jdtls (lsp4j) sends a null result as `{"id": n}` with no `result` field. The client dropped it and waited 30 s, and three such timeouts tripped every jdtls snapshot.
- **Push settle after workspace-level ops:** the ts6 artifact above. Fixed by the r1_history guard and by the engine.
- **Auto-import completion items:** they depend on how warm the server's index is. In the #8946 validation they produced confirmed post-fix differences after a single navigation request. Main excluded them in the completion normalizer; see `data/lsptest/validation/known_bugs.md` for old and new counts.
- **`reduce.py`:** a pinned `open` could keep a `close` that only the pinned open needed. Fixed with a final ddmin pass after pins are dropped (caught by a unit test).

## Limits

- **Budget:** 6 histories per server; H1 and H6 run only inside H7, and seeds other than 2 were not piloted.
- **Chain mode (rust-analyzer):** the step bodies are replayed, but the intermediate snapshots are not. Differences that need those intermediate queries are dropped as non-reproducing.
- **Settle cost:** since the engine fix, open documents the server never republishes after a workspace-level op keep later settles at the 10 s grace (ts6: four settles of 10–14 s in one history).
