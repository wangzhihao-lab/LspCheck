## Tool artifacts found and fixed

- R2, fresh-handle ordering: fresh handles were minted twice and resolved afterwards; JDT LS keeps only its latest completion list resolvable, so every first fresh resolve failed and all completion handles were 'not comparable'. Now each round mints and resolves at once (JDT LS completion handles became comparable: 9 candidates per build).
- R2, completion probe: ts7 returns ~1070 unfiltered items and the first 12 by sortText were locals, so no import-bearing item was ever probed. The probe now lists items as an editor filters them: prefix matches first, then items hinting at an import.
- R2, shift variants: import edits land at the top of the file, which the shifts at, below or after the handle never moved (stale and fresh edits agreed trivially). Added the 'top' variant.
- R3(d), closed files: typescript-language-server answers definition only for open documents, which produced 14 false 'definitionConsistency:lost' candidates on ts6. A reference's file is now opened (and the session settled) before asking there, as an editor does.
- R3(d), library references: references inside node_modules (a vitest .d.ts analysed in another program) are skipped, as target selection skips those directories.
- R3(d), legitimate site differences are labelled (definitionConsistency.signature, .shorthand) instead of mixed with unexplained differences.
- R5, folding ranges: the mapping shifted folding-range lines but not characters; after T6 (inline comment) ts7 correctly moved a fold start from character 59 to 70 and the oracle reported it. Characters are now mapped when present (re-run: 0 candidates).
- R5, T2/T3 near the import block: gopls offers 'Organize Imports' whenever goimports would reformat the import section, so T2's comment right under `import (...)` and T3's whitespace on import lines produced 16 codeAction:extra candidates (legitimate but systematic). T2 is now blank + comment + blank and T3 leaves the lines above the insertion point alone (re-run: 0 candidates).
- R5, planner: T6 does not apply to JSX files and its slot fell on a .tsx file, so T6 never ran; a kind that does not apply to one file now tries the next.
- Engine (fixed by the owner of driver.py / settle.py after reports): a push session for a server that always advertises diagnosticProvider still pulled (R3(a) on rust-analyzer was pull vs pull); PullSettle never settled pyright in pull mode (its own progress per pull counted as a disturbance). Both R3(a) results in this report were re-run after the fixes.

## Known limits

- One seed and a small budget: 2 files x 8 positions per project; R2 12 cases, R5 one case per kind (6), R3 all targets.
- R2(b) delta arithmetic was not exercised: only rust-analyzer declares full/delta and it answers with full tokens after any edit; the check reduced to full vs full (4 rounds, equal).
- R2(a) covers what each server offers: no comparable handles on pyright (resolve adds no edits) and none on ts6 code actions (no `data`).
- R3(a) is weak in this pilot: pyright's target files carry 1 and 0 diagnostics, rust-analyzer's 0 and 0.
- R3(b) checked 6 ranges per server (3 per file).
- R2 replays use the in-session fresh handle (resolved twice) as the control; R3 (b)-(d) replays use two fresh sessions with only the requests the check needs; R5 replays query only the key (same open files).
- T6 does not apply to Python (no block comments) and is skipped in JSX files; R5 completion keys exclude auto-import items (engine normalization).
- The pilot driver (pilot_r2r3r5.py) and the aggregation script were kept outside the repository (file restriction); their command lines are listed below and can be folded into campaign.py.
